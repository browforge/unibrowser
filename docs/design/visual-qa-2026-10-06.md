## VQA-01, VQA-02, and VQA-13 resolution

Status: fixed and re-captured on 2026-10-06.

### Root cause

The black rectangle was not Monaco and was not a Monaco theme fallback.
`#image-compare-host` retained its `hidden` class, but the later
`.image-compare-host { display: flex; ... }` rule overrode the intended hidden
state. The absolute image-compare host, with background `rgb(30, 30, 36)`, sat
above the editor. Monaco remained live underneath it.

The decisive DOM stack at the centre of the editor was:

1. `#image-compare-host.image-compare-host.hidden`, `display:flex`,
   `position:absolute`, `background:rgb(30, 30, 36)`, 822 x 678.
2. `.view-lines`
3. `.lines-content.monaco-editor-background`
4. `.monaco-editor`
5. `#text-editor-host`

The fix adds an explicit `.image-compare-host.hidden { display: none; }`.
Capture-only text mirrors were removed. Evidence now contains the real Monaco
gutter, line numbers, token spans, squiggles, and scrollbar.

### Eliminated hypotheses

- **Theme DTO:** logged DTOs use `base: "vs"` / `base: "vs-dark"` and only
  `#RRGGBB` values. Light editor colours are background `#FFFFFF`, foreground
  `#1F2326`; dark colours are background `#232526`, foreground `#F0EFEB`.
- **Computed styles:** `.monaco-editor-background` computed to
  `rgb(255, 255, 255)` light and `rgb(35, 37, 38)` dark. `.view-line span`
  computed to `rgb(31, 35, 38)` light and `rgb(240, 239, 235)` dark.
- **Layout:** host and Monaco both measured 838 x 694 after `layout()`;
  `automaticLayout` is enabled and explicit layout nudges run before capture.
- **Font:** the computed Monaco stack is `"Source Code Pro",
  "DejaVu Sans Mono", monospace`; 12 px rendered successfully.
- **WebKitGTK flags:** before the overlay fix, all four combinations (both
  flags, DMABUF only, compositing only, neither) produced the identical solid
  crop: mean luma `0.119341`, standard deviation `0`. Therefore
  `WEBKIT_DISABLE_COMPOSITING_MODE` and `WEBKIT_DISABLE_DMABUF_RENDERER` were
  not the cause.
- **Native HTTP child webview:** preventing eager creation changed
  `native content webview present=true` to `false`, but the black rectangle
  remained until the hidden image-compare host was fixed.

### Pixel proof and capture gate

The post-fix TypeScript light crop changed from a solid surface
(`mean=0.119341`, `std=0`) to a painted editor (`mean=0.983825`,
`std=0.0994431`).

The capture command now receives the actual editor rectangle and viewport.
After PNG capture, Rust samples the text area and requires:

- at least 55% pixels matching the expected light/dark theme background;
- at least 100 non-background ink pixels;
- ink on at least 12 pixel rows.

A blank editor and a wrong-colour overlay both fail unit tests. Passing capture
counts:

| --- | ---: | ---: | ---: |
| TypeScript light | 11,144 | 146 | 231,791 / 244,584 |

## Command Manager and Problems correction

Status: fixed and re-captured on 2026-10-06.

### Root causes

The Command Manager model was populated. Rust resolved 14 Markdown controls,
7 TypeScript controls, and 8 PDF controls, and IPC delivered the same counts.
Three presentation faults made the row look empty:

1. Light theme CSS still forced `#1F2326` text and SVG strokes after the shell
   changed to dark slate `#172532`. The `!important` colour also defeated the
   disabled-state colour.
2. JavaScript already selected complete groups for overflow, but CSS hid all
   low-priority groups again when overflow was active or the viewport was under
   1100 px. Their dividers remained.
3. A persisted Large density produced 47 px controls inside a 40 px row because
   the compact height used `!important`. Capture now selects Compact
   deterministically, and the Large row owns its 64 px height.

The old gate compared foreground with a transparent button background as if it
were opaque black, accepted 2.5:1, and did not require a visible label or SVG
box. The corrected gate finds the nearest opaque ancestor, uses relative
luminance, requires 3:1, and requires non-zero control, label, and 16 px SVG
geometry.

The Problems data binding already returned three rows. The failure was CSS:
`hidden` had no rule for the empty state, table wrapper, table, or detail. Thus
`No problems` remained visible while the real table rendered underneath. The
10 rem panel plus automatic first-row detail also clipped the table. Scoped
hidden rules, a 12 rem populated height, fixed table columns, and opt-in row
detail keep all three rows within the table viewport.

computed colour, nearest opaque background, contrast, label box, and SVG box.
